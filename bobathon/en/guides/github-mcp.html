Template 07

Connect a GitHub repository

Connect the official GitHub MCP in read-only mode to review repository, issue, and pull request information.

What this MCP enables

  • Find and summarize repository files and commit information.
  • Review the status and discussion of issues and pull requests.
  • Summarize progress and remaining work across multiple tasks.

Try asking Bob

Start with the read-only URL for the official remote server.

Connect the official remote GitHub MCP to the current project in read-only mode.
Keep the existing MCP configuration and do not put tokens in the configuration file or chat.
After configuration, explain OAuth authentication and how to verify the connection.

1. Add a read-only configuration

  1. In Bob, choose Settings → MCP → + (Add MCP Server).
  2. Under current project scope, select Open Configuration File.
  3. Add the entry below inside mcpServers in .bob/mcp.json.
{
  "mcpServers": {
    "github": {
      "type": "streamable-http",
      "url": "https://api.githubcopilot.com/mcp/readonly",
      "disabled": false
    }
  }
}
Why use the read-only URL?/readonly excludes tools that change GitHub state-such as creating issues, editing files, or merging pull requests-at the server level.

2. Authenticate with GitHub

  1. Save the configuration and turn on Use MCP Servers.
  2. Select Authenticate beside the github server.
  3. In the browser, review the GitHub account and requested permissions, then approve them.
  4. Organization repositories may require approval under organization policy or from an administrator.
Important: Do not paste a GitHub password or personal access token into chat or the configuration file. Sign in only through Bob's OAuth page.
Success: The github server is connected and repository, issue, and pull request read tools appear.

3. Verify connection information

Use GitHub MCP to identify the currently authenticated user,
then show only five accessible repository names.
Do not modify repositories, issues, or pull requests.
Success: The signed-in user and accessible repositories are displayed.

4. Review repository status

In GitHub [owner/repository], find up to five open issues and five open pull requests.
Put the number, title, author, latest update date, and link in a table.
Do not add comments or change status.

5. When you need write access

Change to the base URL https://api.githubcopilot.com/mcp/ only after you have fully reviewed the target with the read-only connection. Before any change, have Bob show the branch, repository, issue number, and planned action again, then approve each write action yourself.

Note: /x/all enables every toolset. Do not use it unless you have a clear reason.

6. Disconnect after the exercise

  1. Reset github authentication from Bob's MCP screen.
  2. Delete or disable the github entry in .bob/mcp.json.
  3. Remove connections you no longer need from the authorized applications list in your GitHub account.

Start safely

  • Start with the /readonly URL.
  • Review the account and permissions on the OAuth page.
  • Do not auto-approve write tools.
  • Follow your organization's repository policies.

If private repositories are not visible, check your account permissions and the organization's OAuth policy.
