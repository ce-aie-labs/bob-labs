GitHub 저장소 연결하기

공식 GitHub MCP를 읽기 전용으로 연결해 저장소, 이슈, Pull Request 정보를 확인합니다.

이 MCP를 연결하면

  • 저장소의 파일과 커밋 정보를 찾아 요약할 수 있습니다.
  • 이슈와 Pull Request의 상태와 논의를 확인할 수 있습니다.
  • 여러 작업의 진행 상황과 남은 할 일을 정리할 수 있습니다.

Bob에게 이렇게 요청해보세요

처음에는 공식 원격 서버의 읽기 전용 주소로 연결합니다.

현재 프로젝트에 공식 원격 GitHub MCP를 읽기 전용으로 연결해줘.
기존 MCP 설정은 유지하고, 토큰을 설정 파일이나 채팅에 넣지 마.
설정 후 OAuth 인증과 연결 확인 방법도 알려줘.

1. 읽기 전용 설정 추가

  1. Bob의 설정 → MCP → + (Add MCP Server)를 선택합니다.
  2. 현재 프로젝트 범위에서 Open Configuration File을 누릅니다.
  3. .bob/mcp.json의 mcpServers 안에 아래 항목을 추가합니다.
{
  "mcpServers": {
    "github": {
      "type": "streamable-http",
      "url": "https://api.githubcopilot.com/mcp/readonly",
      "disabled": false
    }
  }
}
왜 읽기 전용 URL인가요?/readonly는 이슈 생성, 파일 수정, PR 병합처럼 GitHub 상태를 바꾸는 도구를 서버 수준에서 제외합니다.

2. GitHub 인증

  1. 설정을 저장하고 Use MCP Servers를 켭니다.
  2. github 서버 옆의 Authenticate를 선택합니다.
  3. 브라우저에서 사용할 GitHub 계정과 요청된 권한을 확인하고 승인합니다.
  4. 조직 저장소라면 조직 정책 또는 관리자의 승인이 필요할 수 있습니다.
중요: GitHub 비밀번호나 Personal Access Token을 채팅 또는 설정 파일에 붙여 넣지 마세요. Bob의 OAuth 인증 화면에서만 로그인합니다.
성공 기준: github 서버가 연결 상태이고 저장소·이슈·Pull Request 읽기 도구가 표시됩니다.

3. 연결 정보 확인

GitHub MCP로 현재 인증된 사용자 이름을 확인하고,
접근 가능한 저장소 이름 5개만 보여줘.
저장소, 이슈, Pull Request를 수정하지 마.
성공 기준: 로그인한 사용자와 접근 가능한 저장소가 표시됩니다.

4. 저장소 현황 살펴보기

GitHub의 [소유자/저장소]에서 열린 이슈와 Pull Request를 각각 5개까지 확인해줘.
번호, 제목, 작성자, 최근 업데이트 날짜, 링크를 표로 정리해줘.
댓글을 달거나 상태를 변경하지 마.

5. 쓰기 기능이 필요할 때

읽기 전용 연결로 작업 대상을 충분히 확인한 뒤에만 기본 URL https://api.githubcopilot.com/mcp/로 바꾸세요. 변경 전 브랜치, 저장소, 이슈 번호와 실행할 작업을 Bob이 다시 보여주게 하고 각 쓰기 작업을 직접 승인합니다.

주의: /x/all은 모든 도구 모음을 활성화합니다. 필요한 이유가 명확하지 않다면 사용하지 마세요.

6. 실습 후 연결 해제

  1. Bob의 MCP 화면에서 github 인증을 초기화합니다.
  2. .bob/mcp.json에서 github 항목을 삭제하거나 비활성화합니다.
  3. GitHub 계정의 승인된 애플리케이션 목록에서 더 이상 필요 없는 연결을 해제합니다.

안전하게 시작하기

  • /readonly URL부터 사용합니다.
  • OAuth 화면에서 계정과 권한을 확인합니다.
  • 쓰기 도구는 자동 승인하지 않습니다.
  • 조직 저장소 정책을 따릅니다.

비공개 저장소가 보이지 않으면 계정 권한과 조직의 OAuth 정책을 확인하세요.
