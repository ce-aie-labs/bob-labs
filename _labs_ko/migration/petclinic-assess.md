## 문제

몇 년째 아무도 안 건드린 자바 서비스를 넘겨받았습니다. 업그레이드 일정을 잡으려면 먼저 누군가 이걸 읽어야 합니다. 뭘로 만들어졌는지, 뭐가 낡았는지, 어디가 취약한지, 무엇을 먼저 옮겨야 하는지. 이 읽는 일에 하루 이틀이 걸리고, 보통 그것 때문에 업그레이드가 계속 뒤로 밀립니다.

이 랩은 딱 그런 서비스를 하나 주고, 30분 안에 그 답까지 갑니다. Java 설치와 다운로드까지 포함한 시간이고, 이미 갖춰져 있으면 15분이면 됩니다. 코드는 건드리지 않으니 몇 번을 다시 해도 되고, 별도 패키지 없이 됩니다.

## 프롬프트

### Step 1 - Java 21 설치

`java -version` 을 쳤을 때 이미 21 이상이면 건너뛰세요.

**Windows**

1. <https://developer.ibm.com/languages/java/semeru-runtimes/downloads/> 접속
2. **Version 21**, **Windows**, **x64** 를 고르고 **`.msi`** 설치 파일을 받습니다.
3. 실행한 뒤 옵션 화면에서 **Set JAVA_HOME variable** 과 **Add to PATH** 를 켜세요. 기본으로 꺼져 있는 경우가 있습니다.
4. 열려 있는 터미널을 **전부 닫고 새 PowerShell 을 여세요.** 기존 창은 예전 PATH 를 물고 있어서, 설치가 됐는데도 자바가 없다고 나옵니다.

**macOS**

```
brew install --cask semeru-jdk-open@21
```

Homebrew 가 없으면 같은 페이지에서 `.pkg` 를 받아 실행하세요. Apple Silicon 은 **aarch64**, 인텔 맥은 **x64** 입니다.

설치했으면 양쪽 다 이걸로 확인합니다.

```
java -version
```

첫 줄에 `21` 이 나와야 합니다. 그보다 낮으면 이 랩의 나머지가 동작하지 않습니다.

### Step 2 - 애플리케이션 받기

**[bob-lab-petclinic.zip](https://github.com/ce-aie-labs/bob-labs/releases/latest/download/bob-lab-petclinic.zip)** (39 MB) 을 받아 압축을 풉니다. `START-HERE.md` 가 있는 그 폴더에서 터미널을 여세요.

안에 든 건 2019년에 만들어진 동물병원 REST API 인 Spring PetClinic REST 입니다. 자바 파일 99개, 테스트 169개, Java 8, Spring Boot 2.1.5.

### Step 3 - 지금 잘 도는 걸 눈으로 봅니다

아무것도 건드리기 전에 이걸 먼저 보는 게 중요합니다. 이 앱은 고장난 게 아니라 오래된 겁니다.

```
java -jar petclinic-legacy.jar
```

뜨는 데 5초쯤 걸립니다. 그다음 브라우저에서 이 주소를 여세요.

```
http://localhost:9966/petclinic/swagger-ui.html
```

이 앱이 원래 갖고 있는 API 콘솔입니다. 이 서비스가 제공하는 기능이 전부 목록으로 나옵니다 - `GET /vets`, `POST /owners`, `GET /pets` 같은 것들이요. 아무거나 하나 펼치고 **Try it out** → **Execute** 를 누르면 실제 응답이 옵니다. 수의사 여섯 명이 이름까지 나옵니다.

앱은 켜둔 채로 두세요. 다음 랩 마지막에 이 주소로 다시 돌아옵니다.

### Step 4 - 지금 상태를 숫자로 봅니다

앱은 켜둔 채로 **두 번째 터미널**을 열고, 같은 폴더에서:

```
java check.java
```

Java 21 로 빌드해 보고, 컴파일된 바이트코드를 직접 읽어서 알려줍니다. 처음에는 라이브러리를 받느라 몇 분 걸립니다. 여기서 나오는 건 전부 실제로 실행해서 얻은 값이지, 누가 그렇다고 말한 값이 아닙니다.

### Step 5 - Bob에게 물어봅니다

Bob에서 `app` 폴더를 열고 **Agent 모드**에서 이걸 넣으세요.

```
이 저장소를 Java 21 + Spring Boot 3.x 로 올리려고 합니다.

먼저 지금 상태부터 알려주세요.
- 뭘로 만들어져 있는지 (자바 버전, 빌드 도구, 프레임워크와 각 버전)
- Java 21 에서 깨질 곳 (javax → jakarta, 없어진 API, 21에서 못 도는 빌드 플러그인)
- 지금 쓰는 라이브러리 중에 알려진 취약점이 있는 것. 패키지 이름과 지금 고정된
  버전까지 같이 알려주세요.

그다음 어떤 순서로 올려야 하는지 알려주세요. 한 번에 가도 되는지, 중간 버전을
거쳐야 하는지, 왜 그 순서인지.

아직 코드는 고치지 마세요.
```

## 기대 결과

- [ ] 실제 스택을 이름으로 짚음: Java 8, Spring Boot 2.1.5.RELEASE, Maven, Hibernate 5.3.10, 내장 Tomcat 9.0.19, springfox-swagger 2.6.1 - 스프링 앱 일반론이 아니라 `pom.xml` 을 읽고 나온 값
- [ ] `javax` → `jakarta` 패키지 이름 변경이 Spring Boot 3 때문에 강제된다는 점과, **이 코드의 어디에** 걸리는지. 그냥 상식 나열이 아니라
- [ ] 한 번에 점프하지 말고 단계로 - Boot 2.1 → 2.7 → 3.x. 2.7 이 `javax` 를 쓰는 마지막 버전이고, 두 가지를 한꺼번에 옮기면 실패 두 개를 동시에 디버깅하게 되기 때문
- [ ] 취약한 라이브러리를 이름과 고정 버전으로 - `jackson-databind`, `tomcat-embed-core` 9.0.19, `snakeyaml`, `logback-core` 1.2.3, `postgresql` 42.2.5 가 실제로 들어 있습니다
- [ ] 파일이 하나도 안 바뀜. Bob이 편집을 시작했으면 그렇다고 말하고 조사부터 다시 시키세요

## 팁

- 0/3 으로 시작하는 게 정상입니다. 앱이 고장났다는 뜻이 아니라 아직 Java 21 로 안 옮겨졌다는 뜻이고, Step 3 에서 본 API 콘솔이 그 증거입니다. 그래서 그 단계가 먼저 있습니다.
- Step 4 에서 왜 빌드가 실패했는지는 `build.log` 에 있는데, 진짜로 알아보기 어렵습니다. `The forked VM terminated without properly saying goodbye` 로 시작하는 줄을 찾아 그대로 Bob에 붙여넣고 무슨 뜻인지 물어보세요. 이런 메시지에서 답을 바로 얻는 게 Bob을 쓰는 이유의 절반입니다. (뒤에 붙는 종료 코드 숫자는 JVM 마다 달라서 신경 쓰지 않아도 됩니다.)
- Bob이 "의존성을 최신화하고 Jakarta EE 로 옮기세요" 같은 일반론만 내놓으면 코드를 안 읽은 겁니다. `pom.xml` 에 실제로 적힌 버전을 대라고 하면 그때 찾아봅니다.
- 순서에 대해서는 꼭 이유를 물으세요. 팀에 설명할 수 없는 계획은 계획이 아니고, 이건 Bob이 잘 답하는 질문입니다.
- 답변을 저장해 두세요. 다음 랩에서 실제로 업그레이드를 돌리는데, 그 결과를 이 계획과 대조하는 게 워크플로가 알아서 한 일을 확인하는 가장 빠른 방법입니다.

## 응용

1. **우리 회사 저장소로**: 같은 프롬프트를 그대로 우리 자바 프로젝트에 쓰면 됩니다. Bob에 열고 똑같이 세 가지를 물어보세요. 뭘로 돌고 있는지, 뭐가 깨지는지, 어떤 순서인지.
2. **보안만 따로**: `이 프로젝트 의존성 중에 알려진 취약점이 있는 걸 알려주세요. 패키지, 지금 고정된 버전, 그리고 몇 버전부터 고쳐졌는지까지요.` 업그레이드가 아직 승인 안 났는데 위에서 노출 현황을 묻는 상황에 단독으로 씁니다.
3. **착수 전에 범위 재기**: `이 조사 결과를 보고, 자동으로 하면 안 될 것 같은 부분과 사람이 꼭 봐야 할 부분을 알려주세요.` 회의에 들고 가기엔 "잘 될 것 같습니다"보다 범위를 짚은 답이 낫습니다.
