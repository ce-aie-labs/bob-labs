## 문제

이미 잘 돌아가는 코드에 작고 정밀한 수정만 필요한 상황 - 불안정한 호출을 재시도 로직으로 감싸거나, 검증 가드를 넣거나. 그런데 그거 하나 하겠다고 에이전트가 파일 전체를 갈아엎는 건 원치 않는다.

## 프롬프트

리터럴 코딩은 사이드바가 아니라 *파일 안에* 직접 쓰는 지시문이다. 커서를 바꿀 위치에 두고, 리터럴 코딩을 켠 다음(매직완드 아이콘 또는 `Cmd + I`), 지시문을 해당 코드 바로 위에 인라인으로 입력한다:

```
아래 호출은 가끔 실패해. 재시도 로직으로 감싸줘. 몇 번 재시도하고
지수 백오프 넣고, 주변 코드는 건드리지 마.
```

그다음 **Generate**(또는 `Cmd + Enter`)를 누르고, diff를 확인한 뒤 **Accept**.

## 기대 결과

- [ ] 변경이 그 자리에서 diff로 표시됨 - 추가된 줄은 초록, 삭제된 줄은 빨강 - 조용히 덮어쓰는 게 아니라 저장 전에 뭐가 바뀌는지 정확히 읽을 수 있음
- [ ] 수정이 커서 위치에 한정됨: 재시도 래퍼가 대상 호출 주변에만 생기고 파일의 나머지는 그대로 - 파일 전체가 재포맷되지 않음
- [ ] 파일 언어에 맞는 진짜 컴파일되는 코드가 생성됨 - 주석이나 `TODO`가 아니라 - 그리고 수락하면 자연어 지시문 줄 자체는 사라짐
- [ ] Accept All을 하거나, 블록을 하나씩 넘기며 개별 거절도 가능 - 승인하기 전까지는 파일에 아무것도 쓰이지 않음

IBM Bob Level 3 Assist 모듈 [Literate Coding](https://ibm.github.io/bob-l3/assist/1-1/) 기준입니다. Galaxium Travels 데모에서 불안정한 항공편 조회 호출을 `loadFlightsWithRetry` 헬퍼로 감싸고, 한 줄짜리 인라인 주석으로 이메일 검증을 추가하는 과정을 다룹니다.

## 팁

- 리터럴 코딩은 한 파일 안의 집중된 수정용이다. 여러 파일에 걸치거나 구조를 바꾸는 변경은 Agent 모드를 쓸 것 - 여기서 억지로 하면 도구와 싸우는 셈이다.
- 생성된 코드가 컴파일이 안 되면, 다시 돌리기 전에 먼저 예상과 대조해 볼 것. 생성은 비결정적이라 한 번의 Generate가 어쩌다 이상한 결과를 낼 수 있고, 다시 돌리면 해결되는 경우가 많다.
- 여러 수정을 한꺼번에 큐잉할 수 있다: 같은 파일 여러 지점에 지시문 줄을 심어두고 Generate를 한 번만 눌러 한꺼번에 적용.

## 응용

1. **가드 절 추가**: "`<입력>`이 올바른 형식인지 사용 전에 검증하고, 아니면 명확한 에러와 함께 조기 반환해줘."
2. **에러 처리 추가**: "이 블록을 try/catch로 감싸고, 에러를 디버깅에 충분한 맥락과 함께 로깅해줘. 삼켜버리지 말고."
3. **헬퍼로 추출**: "이 로직을 이름이 잘 지어진 헬퍼 함수로 빼줘. 동작은 동일하게."
