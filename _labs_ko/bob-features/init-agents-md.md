## 문제

Bob은 새 대화를 열 때마다 백지에서 시작한다 - 프로젝트를 처음부터 다시 발견하고, 파일을 다시 읽으며, 정작 작업을 시작하기도 전에 시간과 토큰을 태운다. `/init`은 그 지식을 한 번 캡처해서 매 대화 시작에 자동으로 로드되게 한다.

## 프롬프트

**Agent 모드**에서 실행:

```
/init
```

올라오는 파일 쓰기 요청을 승인한다. 그다음 생성된 `AGENTS.md`를 열어서 훑어본다.

## 기대 결과

- [ ] *내 프로젝트*를 구체적으로 설명하는 루트 `AGENTS.md` - 실제 스택, 빌드/테스트/실행의 실제 명령어(그리고 각각 어느 하위 디렉터리에서 도는지), 디렉터리 구조 - 일반적인 보일러플레이트가 아니라
- [ ] 새로 온 사람이 걸려 넘어질 비자명한 함정을 잡아냄(이제 없는 컬럼, 두 군데를 패치해야 하는 테스트, DELETE가 아니라 POST인 취소 흐름) - 해피패스만이 아니라
- [ ] 모드별 규칙 파일도 `.bob/` 아래에 생성됨(`rules-agent/`, `rules-ask/`, `rules-plan/`), 각 모드에 필요한 것에 맞춰짐 - Plan에는 아키텍처 제약, Agent에는 코딩 함정
- [ ] 다음 대화부터 Bob이 전부 다시 읽지 않고도 프로젝트 질문에 답함 - 새 채팅에서 구조 질문을 던져 재스캔을 건너뛰는지 확인

IBM Bob Level 3 Tailor 모듈 [/init and AGENTS.md](https://ibm.github.io/bob-l3/tailor/3-1/) 기준입니다. Galaxium Travels 레포에서 `/init`을 돌리자 `AGENTS.md`와 모드별 파일 3개가 생성되었고, "이제 `seats_available` 컬럼은 없다", "MCP 도구는 FastAPI 의존성 주입을 우회한다" 같은 함정을 짚어냈습니다.

## 팁

- 큰 변경 후에는 `/init`을 다시 돌릴 것(새 모듈, 재구성된 트리, 새 프레임워크). 컨텍스트가 낡지 않게 - Bob의 레포 지도를 최신으로 유지하는 유일한 명령어다.
- 생성된 `AGENTS.md`는 손으로 고칠 수 있는 평범한 파일이다. 자동 스캔이 놓칠 비즈니스 규칙이나 배포 컨벤션을 직접 추가할 것.
- 큰 레포에서는 선택이 아니다: `AGENTS.md`가 없으면 Bob은 매 대화 시작마다 작업 대신 파일을 다시 읽는 데 컨텍스트 윈도우를 쓴다.

## 응용

1. **변경 후 갱신**: "`/init`을 다시 돌려서 방금 추가한 `<모듈>`이 반영되게 `AGENTS.md`를 업데이트해줘."
2. **하우스 룰 직접 추가**: `/init` 후 "우리 배포 절차와 생성된 파일은 절대 수정하지 않는다는 규칙을 문서화한 섹션을 `AGENTS.md`에 추가해줘."
3. **제대로 들어갔는지 확인**: 새 채팅에서 "`<기능>`을 추가하려면 어디를 봐야 해?" - 잘 된 `AGENTS.md`라면 Bob이 트리를 다시 읽지 않고도 답한다.
