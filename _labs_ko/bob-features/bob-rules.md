## 문제

매 채팅마다 같은 표준을 다시 타이핑하고 있다 - "docstring 달아줘", "간결하게", "뭐 바꿨는지 남겨줘". Rules는 Bob이 모든 대화에 로드하는 평문 파일이라, 표준을 한 번만 적어두면 레포에 있는 모두에게 자동으로 강제된다.

## 프롬프트

**Agent 모드**에서 실행:

```
다음 규칙을 @/.bob/rules/team_rules.md에 추가하고 모든 대화에서
적용되도록 설정해줘:

- 모든 공개 함수에 간결한 docstring 달기(한 문장이면 충분).
- 주석, docstring, 설명은 짧게 - 짧고 직접적인 문장으로.
- 상호작용이 끝날 때마다 internal-monologue/ 폴더에 짧은 요약을
  저장하기. 타임스탬프와 설명이 들어간 파일명으로, 예:
  2026-01-15_update-readme.md
```

파일 쓰기를 승인한 뒤 `.bob/rules/team_rules.md`를 열어 Bob이 어떻게 구조화했는지 확인한다.

## 기대 결과

- [ ] `.bob/rules/team_rules.md` 파일이 생성됨(폴더가 없으면 Bob이 만듦), 세 규칙이 그냥 붙여넣기가 아니라 명확하게 섹션으로 정리된 지시문으로 바뀜
- [ ] 규칙이 모든 모드(Agent, Plan, Ask)와 모든 새 대화에 적용됨. 다시 말할 필요 없이 - Bob이 매 채팅 시작에 `.bob/rules/`의 모든 것을 읽기 때문
- [ ] internal-monologue 규칙이 진짜 감사 로그를 만듦: 상호작용마다 무엇을 요청했고 무엇을 했는지 기록한 타임스탬프 Markdown 파일
- [ ] `.bob/rules/`가 레포에 커밋되므로 표준이 클론하는 모든 팀원에게 전파되고 일반 코드 리뷰를 거쳐 감 - 각자 다시 설정하는 세팅이 아니라

IBM Bob Level 3 Tailor 모듈 [Bob Rules](https://ibm.github.io/bob-l3/tailor/3-2/) 기준입니다. Galaxium Travels 레포에서 바로 이 세 규칙을 설정하고, 그 결과 생긴 `internal-monologue/` 감사 폴더와 프로젝트 대 글로벌 스코프 구분을 보여줍니다.

## 팁

- 규칙이 안 지켜지면 제대로 연결이 안 됐을 수 있다. Bob에게 "`@/.bob/rules/team_rules.md`의 프로젝트 규칙이 적용이 안 돼, 제대로 설정해줘"라고 할 것. 글로벌 규칙과 에이전트 스코프 규칙이 평범한 워크스페이스 규칙보다 더 엄격히 지켜지는 편이다.
- 규칙 하나는 한 줄로 명확하게. Bob이 해석해야 하는 규칙은 느슨하게 해석된다.
- internal-monologue 패턴은 숨은 기능이다: 모든 변경의 감사 로그, Bob이 나중에 참조할 연속성, 공유 레포에서 팀원에게 투명성을 준다.
- 프로젝트 규칙(`.bob/rules/`)은 레포와 함께 배포되고, 글로벌 규칙은 사용자 디렉터리에 있으며 모든 프로젝트에 적용된다. 팀 컨벤션은 프로젝트에, 개인 취향은 글로벌에.

## 응용

1. **체크리스트를 규칙으로**: "`<영역>`을 건드리는 변경은 반드시 테스트를 포함하고 관련 문서를 업데이트하라는 규칙을 추가해줘."
2. **커뮤니케이션 스타일**: "규칙 추가: 변경은 코드보다 평이한 설명을 먼저, 서론은 세 문장을 넘기지 마."
3. **글로벌로 승격**: "internal-monologue 규칙을 글로벌 규칙으로 옮겨서 이 프로젝트뿐 아니라 모든 프로젝트에 적용되게 해줘."
