## 문제

건드리기 전에 코드 한 조각을 먼저 이해해야 하는데, 그냥 읽으려는 것뿐인데 에이전트가 "친절하게" 파일을 수정하거나 명령을 실행할까 봐 꺼려진다. Ask 모드는 읽기 전용이다: Bob이 설명하고 추적할 뿐, 아무것도 바꾸거나 실행할 수 없다.

## 프롬프트

**Ask 모드**로 전환(모드 선택기)한 뒤, `@/경로` 멘션으로 정확한 코드를 짚어준다:

```
@/<진입점/경로>가 처음부터 끝까지 어떻게 동작하는지 설명해줘. 뭘 하고,
어떤 함수나 모듈을 호출하고, 중요한 상태는 어디에 있고, 처음 수정하는
사람이 가장 놀랄 만한 부분은 어디인지.
```

## 기대 결과

- [ ] 실제 함수, 파일, 데이터 흐름을 짚는 근거 있는 설명 - 짚어준 진입점에서 추적한 것이지, "이런 앱은 보통 이렇게 동작한다"는 일반론이 아님
- [ ] 상태가 어디에 있는지, 걸려 넘어질 비자명한 부분이 어디인지 짚어줌 - 해피패스만 서술하는 게 아니라
- [ ] 파일이 바뀌지 않고 명령이 실행되지 않음 - 선택기에 Ask가 표시되고, 답변 도중 시켜도 Bob은 수정하거나 실행할 능력이 없음
- [ ] `@/경로` 멘션을 썼기 때문에, Bob이 어느 파일인지 추측하는 대신 짚어준 특정 코드에 답변이 고정됨

IBM Bob Level 3 Delegate 모듈 [The Agentic Sidebar](https://ibm.github.io/bob-l3/delegate/2-1/) 기준입니다. Ask 모드를 변경 없이 코드를 이해하기 위한 읽기 전용·설명 중심 모드로 설명하고, 정확한 컨텍스트를 주는 멘션(`@/path/to/file`, `@problems`, `@terminal`)을 소개합니다.

## 팁

- Ask 모드는 낯설거나 민감한 코드를 읽는 안전한 기본값이다: 실수로 수정하거나 실행할 수 없으니 마음껏 탐색할 수 있다.
- 멘션으로 정확히 짚을 것: `@/path/to/file`은 파일 하나, `@/path/to/folder`는 디렉터리 전체, `@problems`는 현재 진단, `@terminal`은 최근 출력을 가져온다.
- 질문이 "이제 바꿔줘"로 넘어가면 Agent 모드로 의식적으로 전환할 것 - 모드 경계가 읽기에서 쓰기로 넘어간다는 신호가 된다.
- `AGENTS.md`가 없으면 큰 레포에서 Ask 답변이 얕게 나올 수 있다. 더 깊고 정확한 설명을 원하면 `/init`을 먼저 돌릴 것.

## 응용

1. **한 경로 추적**: "Ask 모드에서 `<동작>`이 트리거될 때 정확히 무슨 일이 일어나는지 `@/진입점/경로`부터 함수 단위로 따라가줘."
2. **진단 설명**: "`@problems`가 뭘 말하는지, 각각의 원인이 뭔지 설명해줘 - 아직 고치지는 말고."
3. **두 파일 비교**: "`@/경로/a`와 `@/경로/b`가 접근 방식에서 어떻게 다른지, 각각 언제 쓰면 되는지 설명해줘."
