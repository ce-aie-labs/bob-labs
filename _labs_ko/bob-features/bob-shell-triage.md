## 문제

빌드가 실패했거나 서비스가 에러를 뿜고 있고, 터미널엔 로그가 한가득이다. 손으로 스크롤하고 grep하는 대신, 그대로 Bob Shell에 파이프해서 커맨드라인을 떠나지 않고 근본 원인을 읽어낸다.

## 프롬프트

터미널에서, **Bob Shell**이 설치된 상태로, 로그를 headless `bob` 호출에 파이프한다:

```
cat error.log | bob "이 로그 읽고 근본 원인을 한두 문장으로, 그리고 가장
가능성 높은 수정 하나를 알려줘. 어느 줄이나 설정이 잘못됐는지 콕 집어서."
```

## 기대 결과

- [ ] 한두 문장의 근본 원인 진단 - 에러 텍스트를 바꿔 쓴 게 아니라 실제로 실패하는 줄이나 조건
- [ ] 가장 가능성 높은 수정 하나를 구체적으로 지목(특정 명령어, 파일, 설정값) - 다섯 가지 시도해보라는 목록이 아니라
- [ ] headless로 동작함: 로그가 파이프로 들어가고 Bob이 터미널에서 답함. IDE도 대화형 세션도 없이 - 그래서 그대로 스크립트나 CI 단계에 넣을 수 있음
- [ ] Bob Shell의 더 엄격한 기본값이 유지됨: 수정이 파일 쓰기나 명령 실행을 뜻하면, 멋대로 하지 않고 먼저 물어봄

IBM Bob Level 3 Scale & Extend 모듈 [Bob Shell](https://ibm.github.io/bob-l3/scale/4-2/) 기준입니다. headless 모드(`cat error.log | bob "explain this"`), 일반 셸 명령용 `!` 접두사, 더 엄격한 자동 승인 기본값을 보여줍니다. Delegate 모듈에서는 같은 방식 - 143줄짜리 실패 로그를 Bob에 넘기기 - 으로 오래된 데이터베이스 파일을 진짜 원인으로 짚어냈습니다.

## 팁

- Bob Shell은 IDE 확장과 별도로 설치되고 첫 실행 시 IBM 로그인을 요구한다. 이 랩은 이미 세팅됐다고 가정한다 - 설치는 IBM 제품 문서 참고.
- headless 모드가 핵심 무기다: `cat <아무거나> | bob "<질문>"`은 Bob을 스크립트 가능한 컴포넌트로 만든다. 컴파일러 출력, 스택 트레이스, 로그를 파이프해 분석하고, 빌드 단계로 요약을 생성.
- 대화형 Bob Shell 세션 안에서는 줄 앞에 `!`를 붙여 일반 셸 명령을 실행하고(`!git diff`), `Esc`를 눌러 Bob으로 돌아온다.
- 독립적인 작업은 여러 Bob Shell 인스턴스를 병렬로 - 하나는 로그 분석, 하나는 테스트 작성 - 터미널에선 쉽고 IDE에선 번거롭다.

## 응용

1. **실패한 테스트 진단**: `npm test 2>&1 | bob "어느 테스트가 왜 실패했는지 - 단언문과 수정 방법을 짚어줘"`
2. **커밋 전 diff 설명**: `git diff | bob "뭐가 바뀌었는지 요약하고 위험해 보이는 건 표시해줘"`
3. **수정 또는 에스컬레이션**: `cat error.log | bob "한 줄 수정이면 정확한 변경을 제안하고, 더 깊은 문제면 먼저 뭘 조사할지 알려줘"`
